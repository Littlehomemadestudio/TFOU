# TFOU — Naval Combat Sandbox (Unity 6 / URP)

A procedural ocean + warship controller built for Unity **6000.3.x (URP 17.3)**.
Everything visual is generated at runtime — **no textures, no prefabs, no asset
dependencies** beyond the project itself.

![status](https://img.shields.io/badge/Unity-6000.3.9f1-black) ![urp](https://img.shields.io/badge/URP-17.3-blue)

---

## Quick start

1. Open the project in Unity 6000.3.9f1.
2. Drop a ship into the scene (e.g. drag `Assets/S3.prefab` in).
3. Add a **Rigidbody** to the ship root and attach **`master_ship`**.
4. Press Play. The ocean, camera, FX, post-processing and reflections
   bootstrap themselves.

## Architecture

```
master_ship.cs                 orchestrator + engine telegraph + HUD (legacy GUID preserved)
Assets/Scripts/Ocean/
  OceanWaves.cs                8-wave Beaufort Gerstner sea — single source of truth,
                               identical math on CPU (buoyancy) and GPU (vertex shader)
  OceanGridBuilder.cs          3 water rings: near (~1.6 m cells) / mid / horizon,
                               radial detail weight baked into vertex alpha
  OceanQuality.cs              HDR + SMAA + ACES tonemapping/bloom/vignette/grain volume
  WaterPlanarReflections.cs    mirror-camera planar reflections (URP-safe, Water layer culled)
Assets/Scripts/Ship/
  ShipBuoyancy.cs              9-point hull sampling + least-squares plane fit →
                               real pitch/roll over swell, bow-slam events
  ShipCameraRig.cs             4 modes, spring-arm collision, speed shake, FOV punch, bank roll
  ShipEffects.cs               procedural bow spray, bow sheet, stern wake, funnel smoke
  ShipInput.cs                 Input System wrapper (keyboard/mouse/gamepad)
Assets/AutoGeneratedWater/
  AutoOceanWater.shader        the ocean: GPU Gerstner displacement, Jacobian whitecaps,
                               Kelvin-angle wake, SSS, Beer-Lambert absorption, hull
                               refraction, procedural sky + HDR sun disk, glitter specular
  AutoSoftParticle.shader      textureless soft radial particles for all ship FX
```

### Why the ship never "floats wrong"

`OceanWaves` builds the spectrum once and pushes it to the GPU as global
uniforms (`_GerstA/_GerstB`). The vertex shader displaces the grid and derives
normals + the Jacobian analytically; `ShipBuoyancy` evaluates **the same
closed-form field** at 9 hull points. Visuals and physics cannot diverge.
The CPU never rewrites mesh data — per-frame water cost is zero upload.

| Tier | Post FX | Planar reflections | FX density |
|---|---|---|---|
| Low | ✗ | ✗ | 0.4× |
| Medium | ✓ | ✗ | 0.75× |
| High | ✓ | ✓ (½ res, every 2nd frame) | 1× |

## Tuning cheat-sheet

- **Rougher seas:** `seaState` (Beaufort 0–10) or live with `O`/`P`.
- **Wave look:** `waveChoppiness` (curl), `waveLengthScale`, `waveSpeedMultiplier`.
- **Colors:** deep/crest/foam/sky colors feed both water body and procedural sky.
- **Sun glitter:** `sunSpecPower` ↑ = tighter path, `sunSpecIntensity`, bloom picks up the HDR sun disk automatically.
- **Wake:** `wakeStrength`, auto-scaled to hull length/beam.
- **Performance:** lower `nearRingResolution` first, then `qualityTier`, then `planarReflections`.

## Suimono 2 integration (Mothership)

The repo carries the Suimono 2 script suite in `Assets/Scripts/SCRIPTS/`
(namespace `Suimono.Core`). **`Mothership.cs` is the plug-and-play assembler**:
attach it — and only it — to a ship root and it builds the full stack.

```
Mothership (attach to ship)
  ├─ ensures Rigidbody + master_ship
  ├─ detects a scene SUIMONO_Module  ── found ──▶ SUIMONO water = the original system
  │        └─ not found ─────────────────────▶ procedural ocean fallback
  ├─ buoyancy style:
  │    HybridMasterShip (default)  master_ship handling, floating on Suimono
  │                                waves via SuimonoBridge (SuimonoGetHeightAll)
  │    PureSuimono                 spawns an fx_buoyancy cluster under the hull
  │                                (applyToParent, splitFac force sharing);
  │                                master_ship only feeds thrust + rudder
  ├─ wires module.setCamera / module.setLight
  ├─ fx_soundModule + AudioSource holder (assign your clips)
  └─ optional experimental fx_EffectTrail wake
```

**To activate Suimono water:** import your purchased Suimono 2 asset into the
project and drop its `SUIMONO_Module` prefab into the scene (name must stay
`SUIMONO_Module` — the Suimono scripts find it by that name). Mothership
auto-detects it at Play; the HUD shows which backend is live.

**URP caveats for the Suimono suite:**
- `SuimonoDepth`, `SuimonoCamera_depth`, `Suimono_DistanceBlur`,
  `Suimono_UnderwaterFog` are `OnRenderImage`-based → **inert under URP**.
  They compile, but URP never calls that callback. The underwater look under
  URP would need a ScriptableRendererFeature port (roadmap item).
- `fx_EffectTrail`'s mesh builder is partially commented out in this drop and
  needs a Suimono trail material — that's why the wake defaults to the
  procedural Kelvin wake + particle churn, which work on both backends.
- ⚠️ Licensing: `SCRIPTS/` contains Suimono 2 **source code**. Publishing it
  in a public repo is a bigger Asset Store EULA exposure than binaries were.
  Strongly consider making this repo private or removing that folder from
  history.

## Notes & caveats

- `Assets/SUIMONO - WATER SYSTEM 2/` and `Assets/Military vehicles (Sea)/` are
  **Unity Asset Store content**. ⚠️ The Asset Store EULA does not permit
  redistributing these in a public repository — consider removing them (and
  their history) or making this repo private. The ocean system itself does not
  depend on them.
- Water renders in the transparent queue (after the depth/opaque copy) so
  contact foam and refraction see ships and terrain; it still writes depth.
- Planar reflections use a manual mirror-camera render; on some mobile
  backends with Native RenderPass this can be expensive — drop to Medium tier.
- `Assets/Scenes/ship.cs` (dead `PlugAndPlay_CruiserController`, file/class
  name mismatch — it never ran) was removed.
